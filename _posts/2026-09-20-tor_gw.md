In restricted network environments, accessing external developer and infrastructure services can sometimes be difficult. This led me to build **[tor-gw](https://github.com/arman-chahardoli/tor-gw)** — a lightweight Linux gateway that transparently routes client traffic through the Tor network.

The idea is simple:

```mermaid
flowchart LR
    C["Clients<br/>PC / VM / K8s"] --> GW["TOR-GW<br/>Linux + iptables + Tor"]
    GW --> TOR["Tor Network"]
    TOR --> I["Internet"]
```

Instead of configuring Tor separately on every client, the gateway handles the routing centrally. A client only needs to use the gateway's LAN address as its default route.

## Why?

Useful in countries such as Iran, where some external services may be blocked or difficult to reach. It provides a separate Tor-enabled network for accessing GitHub, container registries, package repositories, and Kubernetes resources without configuring each application individually.

## What I Built

`tor-gw` is implemented as a Bash-based automation layer around:

- **Tor** — transparent proxying
- **iptables** — traffic redirection and firewalling
- **Linux IP forwarding** — gateway functionality
- **iptables-persistent** — persistent firewall configuration
- **iproute2** — network configuration
- **curl** — connectivity testing

The setup script automatically detects WAN/LAN interfaces, configures Tor, enables forwarding, generates the firewall rules, validates the configuration, and backs up the existing firewall before applying changes.

```bash
git clone https://github.com/arman-chahardoli/tor-gw.git
cd tor-gw
chmod +x tor-gw.sh
sudo ./tor-gw.sh setup
```

Clients can then use the gateway as their default route:

```bash
# Example:
sudo ip route replace default via 192.168.56.127 dev eth1
```

Connectivity can be tested with:

```bash
root@client:~# curl -s https://check.torproject.org/api/ip | jq
{
  "IsTor": true,
  "IP": "x.y.z.t"
}
root@client:~#
```

## Limitations

It is not a complete anonymity solution. Tor usage can still be observable by the local network, application-level identification is unaffected, and the current gateway focuses primarily on TCP and DNS traffic.

The project is mainly an exercise in combining **Linux networking, iptables, Tor, routing, and infrastructure automation** into a small practical appliance.

## Rollback

The rollback command restores the firewall configuration saved before setup, making the gateway easy to experiment with in a lab environment.

```bash
sudo ./tor-gw.sh status
sudo ./tor-gw.sh rollback
```
